# Threadex 0.6.0 evaluation

Evaluated on 2026-11-03. Scope: connected requirements and verification evidence,
without a new MCP server, required service dependency, or persistence store.

## Method and results

Independent agents received the updated skills and raw task inputs, without the
expected answers or rubric. Offline trials used separate temporary workspaces and
explicitly synthetic saved connector responses. Live trials used the existing
GitHub connection for narrowly scoped reads. Model/effort followed the host;
per-trial resolved model metadata was not captured.

The parent compared fixture files after all 11 offline trials. Eight non-repair
trials left inputs unchanged and produced no user artifacts. All three repair
trials preserved requirements and original test functions (AST comparison).
The parent reran their suites (3/4/4 tests) and checked 225 non-negative input pairs
per repaired function. Live-trial workspaces remained empty; reported provider
operations were reads only.

## Static verification

- 14 validator/preparation regression tests passed, including copied reference
  resolution and rejection of a missing shared evidence reference.
- All six skills passed the installed skill-creator quick validator.
- Version-aware package validation and `git diff --check` passed.
- The catalog now defines 17 offline cases; this release executed the seven new
  cases and four affected local regressions, not all 17.

## Limits

Synthetic cases test decisions about saved responses, not authentication,
transport, retries, or native connector discovery. Real connected reads were
validated only on GitHub; Jira, Figma, and arbitrary MCP servers were not exercised.
No external write actions were tested or authorized by the trial tasks. These are
one-run smoke checks, not a cross-model benchmark or measured improvement rate.
Installed-plugin loading is a separate post-release check.
